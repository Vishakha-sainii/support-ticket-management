# Documentation Skill

## Purpose

Produce concise, accurate engineering documentation that reflects the actual implementation and approved specification.

## Documentation Principles

Documentation must:

* be technically accurate
* reflect actual behavior
* avoid unsupported claims
* use consistent terminology
* reference requirement IDs where useful
* include examples when they improve understanding

## Required Documentation

Maintain:

* requirements
* architecture
* API contract
* state machine
* test strategy
* implementation tasks
* AI decisions
* traceability
* README

## Code Documentation

Document complex business rules.

Do not add comments that merely restate obvious code.

Prefer clear code over excessive comments.

## API Documentation

For each endpoint document:

* method
* URL
* request
* response
* status codes
* validation
* error behavior

## Change Management

When behavior changes:

1. update specification
2. update implementation
3. update tests
4. update documentation

Never intentionally allow specification and implementation to drift.

## AI Generated Documentation

AI-generated documentation must be reviewed for correctness.

Do not invent architecture, behavior, APIs or requirements that do not exist.
